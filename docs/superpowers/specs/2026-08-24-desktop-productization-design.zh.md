# DeepSeek Harness 桌面产品化设计

[English](2026-08-24-desktop-productization-design.md) | 中文

## 范围

本设计覆盖 `apps/desktop`、桌面发行工作流，以及 CLI 和 Web 进入桌面安装包所需的最小根配置。CLI 的业务行为、Web 产品界面和独立 Node 后端的进程模型不在改造范围内。

## 目标

- Windows 用户只安装一次 NSIS 安装版，后续在应用内检查、下载并重启完成更新。
- GitHub Fork 根据桌面版本标签自动构建、验证和发布，无需维护者在本机打包。
- Electron 启动后立即显示真实启动状态，后端就绪后在同一窗口进入主界面。
- 正式发布只包含安装包和更新元数据，不发布单文件便携版、展开目录或构建诊断文件。
- 在保留独立 Node、终端、原生模块和子进程行为的前提下，减少安装体积和文件数量。
- 桌面专属改动集中在 `apps/desktop`，降低同步上游 CLI 和 Web 代码时的冲突。

## 非目标

- 不把后端迁移到 Electron 的 Node 运行时。
- 不重写现有 Web 界面，也不在 Web 页面中加入桌面更新组件。
- 不实现便携版的原地更新。
- 不承诺在没有 Windows 代码签名证书时消除 SmartScreen 提示。
- 不改变会话、用户设置和凭据的持久化位置或格式。

## 组件

### 桌面主进程

桌面主进程继续拥有单实例锁、窗口、后端进程和退出顺序。主进程在 Electron 就绪后立即创建主窗口并加载本地启动页面，同时启动后端；后端打印就绪 URL 后，主进程在同一窗口加载该 URL。窗口安全配置继续启用上下文隔离、禁用 Node 集成并启用渲染器沙箱。

### 启动页面

启动页面及其图标作为桌面壳静态资源进入 `app.asar`。页面只显示版本号和真实阶段文本，不显示无法由实际进度支撑的百分比。阶段至少包括“正在启动本地服务”和“正在加载界面”。后端退出、启动拒绝或 90 秒内未就绪时，主进程提供重试、打开日志目录和退出操作。

### 后端启动器

后端启动器继续使用随安装包提供的标准 Node，并执行已构建的 `@deepseek-ai/dsh` CLI。打包阶段把后端依赖闭包物化到 `resources/backend`，使标准 Node 不读取 `app.asar`。桌面壳从 `app.asar` 运行，后端从真实文件系统运行；打包后启动测试验证 CLI 入口、Web 静态资源和原生模块均可解析。

### 更新管理器

更新管理器封装 `electron-updater`，只在已安装的生产构建中启用。应用主界面的“帮助”菜单提供“检查更新”；后台检查在主界面就绪后执行。后台检查失败只记录日志，用户手动检查失败则显示可重试错误。

更新状态依次为检查、可用、下载、已下载和失败。发现新版本时，原生对话框提供“下载更新”和“稍后”；下载进度同步到 Windows 任务栏；下载完成后提供“重启更新”和“稍后”。重启安装前先正常停止后端，再调用更新器退出并安装。校验或安装准备失败时保留当前安装，不覆盖可运行版本。

### 日志

桌面主进程和后端启动输出写入 Electron 用户日志目录。日志记录版本、启动阶段、后端退出信息和更新状态，但不记录环境变量、凭据、用户输入或会话内容。错误界面的“打开日志目录”通过系统文件管理器打开该目录。

## 启动与退出流程

1. 获取单实例锁；第二实例只恢复并聚焦现有窗口。
2. Electron 就绪后设置 Windows AppUserModelID、图标和应用菜单。
3. 创建并显示加载本地启动页面的窗口。
4. 启动独立 Node 后端，并把标准输出和错误输出写入日志。
5. 后端就绪后在同一窗口加载回环 URL。
6. 主界面就绪后执行一次后台更新检查。
7. 用户退出或更新重启时，先请求后端正常结束，超过现有宽限期后再强制结束。

## 发布与版本

桌面应用使用独立语义版本，Git 标签格式为 `desktop-v<version>`。工作流验证标签版本与 `apps/desktop/package.json` 一致，不一致时停止发布。上游项目版本可以独立变化，不直接触发桌面客户端升级。

Windows 发布工作流在 `desktop-v*` 标签上运行，并授予最小的 `contents: write` 权限。工作流在 Windows runner 上安装锁定依赖，构建 CLI、Web 和桌面端，运行聚焦测试与打包后端启动测试，然后生成 NSIS 安装包。所有验证通过后，工作流创建 GitHub Release 并上传安装包、`latest.yml` 和安装包 `.blockmap`；更新源由当前工作流仓库身份生成，因此 Fork 所有者和仓库名不硬编码在源文件中。

现有无更新器版本需要手动安装一次首个产品化安装包。此后安装包使用相同 appId、安装标识和用户数据位置，更新器在原安装位置升级。发布工作流预留 electron-builder 标准代码签名环境变量；存在签名 Secrets 时自动签名，不存在时生成可测试的未签名个人构建。

## 打包与体积

electron-builder 只配置 NSIS 目标。`win-unpacked` 可以作为构建中间目录用于测试，但不上传到 Release；portable 目标、旧便携 EXE 和公开构建诊断文件退出发行流程。

桌面壳进入 `app.asar`，独立 Node 和后端依赖闭包进入 `extraResources`。首轮裁剪排除 source map、TypeScript 构建信息、测试资产、示例资产和非 Windows x64 原生二进制。首轮不全局删除 `.ts` 文件；只有打包清单证明文件不在运行时解析路径、且打包后测试覆盖其消费者时，才增加更窄的排除规则。

构建输出生成体积报告，分别记录安装包大小、展开大小、文件数量和最大的运行时目录。相对于当前基线，展开安装体积至少减少 50 MiB，安装包至少减少 5 MiB；达不到目标时发布检查失败并保留报告，不通过删除未经验证的运行依赖达标。

## 错误处理与安全

- 自动更新仅接受 electron-builder 元数据中匹配的版本、路径和 SHA-512；下载失败允许重试。
- 开发模式默认禁用更新，并支持环境变量显式禁用生产更新检查，便于离线和故障诊断。
- 外部导航继续交给系统浏览器，回环 URL 以外的导航不进入应用窗口。
- 更新下载不获得 Web 页面中的凭据或 Node 权限；更新控制留在 Electron 主进程。
- 代码签名是可信公开发行的发布要求，但不是本地功能验证的前置条件。未签名构建明确标记为个人测试构建。
- 构建诊断文件包含构建机路径，不上传到公开 Release。

## 测试

单元测试覆盖启动 URL 解析、后端就绪和失败、重复结算防护、更新状态转换、后台与手动检查的错误差异、菜单命令和退出更新顺序。加载页面测试验证真实状态文本与失败操作，不依赖虚假计时。

打包后测试直接使用随包 Node 启动随包 CLI，等待 Web 就绪行并请求回环 URL，随后验证正常退出。该测试还验证 Web 静态资源和当前 Windows x64 原生模块存在，防止裁剪规则产生“源码可跑、安装包缺文件”。

真实更新验收发布两个连续测试版本：旧版本发现新版本、下载、重启安装，并在新版本中保留用户设置、会话和自定义安装位置。没有可用新版本、网络中断、下载失败和用户选择稍后的路径也必须保持当前版本可用。

## 验收标准

- 双击安装后的快捷方式后立即出现带正确图标和版本号的加载窗口。
- 后端就绪后同一窗口进入主界面，CLI、Web、终端、文件操作和退出行为保持正常。
- GitHub Actions 可从桌面标签独立完成构建、验证和发布。
- GitHub Release 只包含 NSIS 安装包、`latest.yml` 和 `.blockmap`。
- 应用可以后台和手动检查更新，用户通过下载与重启按钮完成升级。
- 更新失败不会损坏当前安装，升级保留用户数据和安装位置。
- portable 目标与旧便携 EXE 被清理，展开目录只作为短期测试产物。
- 展开体积和安装包分别达到 50 MiB 与 5 MiB 的最小降幅。
- 聚焦单元测试、类型检查、文档检查、构建检查和打包后启动测试通过。
